# xa4y_vidsave_bot

Telegram-бот на Go для скачивания публичных коротких видео из **Instagram Reels**, **TikTok** и **YouTube Shorts**.

## Как работает

1. Получает ссылку в личном чате или группе (также из подписи или скрытого Telegram `text_link`).
2. Проверяет домен и формат URL. Поддерживаются `instagram.com/reel/...`, `tiktok.com/@.../video/...`, `vm.tiktok.com/...`, `youtube.com/shorts/...`, `m.youtube.com/shorts/...`, `youtu.be/VIDEO_ID`.
3. Ищет Telegram `file_id` в PostgreSQL по ключу `platform:video_id`. Если видео уже загружено, отправляет его из кэша.
4. В случае промаха запускает `yt-dlp` с ограничением конкурентных загрузок, после скачивания проверяет размер, хеширует файл и отправляет его через Telegram Bot API.
5. Сохраняет `file_id` в PostgreSQL, позволяет поделиться видео через inline-кнопку и удаляет временные файлы.

## YouTube Shorts

- Только индивидуальные ссылки `/shorts/VIDEO_ID` и короткие ссылки `youtu.be/VIDEO_ID`; плейлисты и `/watch` URL не принимаются.
- Не более **180 секунд**. Для `youtu.be` проверяется длительность, поскольку сам формат короткой ссылки не гарантирует, что ролик является Shorts.
- Приоритет — совместимое H.264 MP4-видео (при недоступности — другое MP4) до 1080 пикселей **по ширине** + M4A-аудио; FFmpeg объединяет дорожки в один MP4.
- Для YouTube используются `yt-dlp[default]` и Node.js (JS challenge solver). `yt-dlp` закреплён на версии `2026.10.26` в Dockerfile/Compose и может быть обновлён через `YT_DLP_VERSION`.
- YouTube периодически меняет требования к неавторизованным запросам (включая PO Tokens). Публичные видео, требующие входа, проверки бота или недоступные на IP VPS, могут не скачиваться. Бот не хранит cookies аккаунтов.
- Telegram Bot API разрешает загружать видео до **50 MiB**. Бот ограничивает загрузку и дополнительно проверяет размер файла перед отправкой.

## Развёртывание

Создать `.env` по `.env.example`, задать `BOT_TOKEN`, `DATABASE_URL`, `POSTGRES_PASSWORD` и другие переменные. Не коммитить настоящий `.env`.

```sh
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 bot
```

`.github/workflows/deploy.yml` автоматически обновляет рабочую копию на VPS после пуша в `main`. `.github/workflows/ci.yml` проверяет Go-тесты, `go vet` и Docker-сборку до слияния PR.

```sh
go test ./...
go vet ./...
```

Проверять работу Telegram-бота в production отправкой своей ссылки. Не запускать второй экземпляр с тем же `BOT_TOKEN`: polling-сессии будут конфликтовать.

## Аналитика и доступ владельца

После обновления бот собирает число пользователей, DAU/WAU/MAU, успешные и неудачные отправки, статистику платформ и кэширования. В личном чате команда `/id` показывает твой Telegram ID. Добавь его в `ADMIN_TELEGRAM_IDS` на VPS для доступа к закрытой `/stats`. Для ChatGPT доступна отдельная read-only утилита `cmd/stats`, запускаемая через `scripts/metrics-readonly.sh` с VPS. Детали, настройка и ограничения исторических данных — [docs/ANALYTICS.md](docs/ANALYTICS.md).

### Локальный отчёт через Desktop Commander

На VPS доступен **только из localhost** агрегированный JSON: `curl --fail --silent --show-error http://127.0.0.1:18873/stats`. Для чтения не нужен токен Telegram, пароль от PostgreSQL или роль с доступом к сырым данным. Эндпоинт не публикуется наружу, возвращает только агрегаты (без Telegram ID). Проверка работоспособности: `curl http://127.0.0.1:18873/healthz`. Управление доступом к команде /stats в самом Telegram — отдельно, через `ADMIN_TELEGRAM_IDS`.

## TikTok Photo Posts · Stage 5

Публикации TikTok с **фотографиями** теперь обрабатываются отдельно от видео: прямые ссылки `/@user/photo/ID` и сокращённые `vt.tiktok.com` / `vm.tiktok.com` со ссылкой на фото. Бот отправляет одну фотографию или альбомы (по 2–10 штук) с сохранением исходного порядка и кэшем Telegram `file_id` для повторных обращений. Медиа из фото-постов не меняют старую метрику уникальных видео.

**Группы без новых статусов:** одно временное `⏳ сек, качаю`, которое удаляется по завершении. Личные чаты: Live Download Widget с неопределённым прогрессом фотографий. Лимиты: 35 фотографий, 10 МиБ на фото, 80 МиБ на пост. Музыка не скачивается.

Функция по умолчанию **выключена** (`TIKTOK_PHOTO_ENABLED=false`), опционально включается только для владельца через `TIKTOK_PHOTO_PILOT_IDS=665731091`; расширение на всех — после E2E-проверки. Требуется `gallery-dl` (в Docker pinned `1.32.19`). [Документация и rollout Stage 5](docs/TIKTOK_PHOTOS_STAGE5.md).

## Error & Info Widget · Stage 4

Новый **информационный виджет ошибки** для YouTube Shorts, Instagram Reels и TikTok: компактная тёмная карточка с объяснением и локальной кнопкой **«Поддерживаемые форматы»**. Кнопка ничего не отправляет на сервер и не повторяет скачивание. Появляется после ошибки вместо временного progress-виджета, а при сбое Widget API бот показывает прежний текст ошибки.

Выпускается поэтапно: `ERROR_WIDGET_ENABLED=false` по умолчанию, в пилоте требуется `DOWNLOAD_WIDGET_ENABLED=true` и `DOWNLOAD_WIDGET_PILOT_IDS=665731091`. Сначала проверяем на владельце, затем расширяем на остальных пользователей. [Подробности и rollback](docs/ERROR_WIDGET_STAGE4.md).

## Live Download Widget · Stage 3

Интерактивная тёмная карточка загрузки для **TikTok, Instagram Reels и YouTube Shorts** работает только в личных чатах и только при явном включении `DOWNLOAD_WIDGET_ENABLED=true`; по умолчанию функция выключена. Для пилота одного владельца указать `DOWNLOAD_WIDGET_PILOT_IDS=665731091`, чтобы не включать новый UX всем сразу.

Точный процент показывается только для текущего файла при известном размере из yt-dlp; для неизвестного размера, постобработки и загрузки в Telegram — неопределённая индикация. Cache hit по `file_id` обрабатывается мгновенно без виджета. Бот сохраняет прежний текстовый fallback и защиту от повторных загрузок, ограниченную очередь и тайм-ауты. **Никаких Retry-кнопок или автоматических новых скачиваний.** [Описание Stage 3 и rollout](docs/DOWNLOAD_WIDGET_STAGE3.md).

## Telegram Analytics Widget · Stage 2

Второй этап [Telegram Widgets v1](docs/WIDGETS_SPEC_V1.md): закрытая панель статистики для владельца, периоды 24ч/7д/30д/всё, график и разбивка по платформам. На production включается **только явно** через `ANALYTICS_WIDGET_ENABLED=true`; по умолчанию старый текстовый /stats и стандартный polling остаются без изменений. Команда `/stats_text` — принудительный текстовый fallback. Подробности в [docs/ANALYTICS_WIDGET_STAGE2.md](docs/ANALYTICS_WIDGET_STAGE2.md).
