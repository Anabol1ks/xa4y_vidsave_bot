**Основная спецификация:** [WIDGETS_SPEC_V1.md](WIDGETS_SPEC_V1.md)

## Что увидит пользователь

При неудачной загрузке **YouTube Shorts, TikTok или Instagram Reels** бот вместо обычной ошибки по возможности показывает отдельную **постоянную информационную карточку** в том же визуальном стиле, что и Live Download: чёрная поверхность, крупный белый заголовок, красноватый акцент ошибки и узнаваемая иконка платформы.

Под заголовком — короткое объяснение. Например:
- Instagram: «Видео закрыто» / «Возможно, требуется вход в аккаунт»;
- Instagram audience restriction: если `yt-dlp` возвращает «This content isn't available to everyone: It can't be seen by certain audiences», выводится `source_restricted` и карточка «Доступ ограничен», а не универсальная ошибка загрузки. Это не позволяет обойти ограничение доступа и не требует cookies. Для примера проверен Reels `DfrHoCYsT_E` с `yt-dlp==2026.10.26`; параметр `xtok` не влияет на ответ.
- TikTok: «Доступ ограничен» / «Платформа временно ограничила скачивание»;
- YouTube: «Видео слишком длинное» (Shorts до 3 минут);
- Любая платформа: «Видео слишком большое» (максимум 50 МиБ), «Ошибка соединения», «Не удалось отправить видео», «Слишком много запросов».
- Неподдерживаемая или некорректная URL-ссылка: нейтральная карточка **XA4Y** с объяснением.

Под каждой карточкой располагается **одна кнопка «Поддерживаемые форматы»**. Она **локально в HTML** раскрывает список:
- Instagram Reels — `instagram.com/reel/…`;
- TikTok — `tiktok.com/@user/video/…`;
- YouTube Shorts — `youtube.com/shorts/…`.

Раскрытие **не отправляет `TelegramWidget.request()`**, не вызывает Bot API, не создаёт задачи скачивания и не меняет серверное состояние. **Кнопок «Попробовать снова», Retry, Download again и скрытых повторов нет.**

## Жизненный цикл и fallback

- При обычной загрузке сохраняется исходный Live Download Widget из этапа 3.
- При ошибке новый Error Widget отправляется **только один раз**; временная карточка прогресса затем удаляется. Это новая карточка, так как Telegram **не поддерживает замену HTML** уже отправленного виджета. Ошибочный статус остаётся в чате, чтобы пользователь мог прочитать описание и раскрыть справку.
- Если отправить Error Widget не удалось, бот отправит **ровно одно прежнее текстовое сообщение** об ошибке. Даже при сбое Telegram Widgets ошибка не должна теряться.
- Для кэш-хитов с ошибкой отправки видео нет прогресс-виджета; бот отправляет Error Widget сразу (или текст при неудаче).
- Для перегрузки и неверных URL действует существующий `downloadGate.shouldNotify`: не более одного предупреждения в чат за 10 секунд. Запросы от кнопки справки отсутствуют.
- **В группах** новые виджеты пока недоступны в Telegram production — остаются обычные текстовые ошибки. Inline-запросы, `/stats`, кэш, аналитика и обычные видео не меняются.
- Видео, которое успешно пришло, остаётся обычным Telegram-видео; только Error Widget является защищённым сообщением, скриншоты с которым могут блокироваться самим Telegram.

## Фиксированная схема данных

Backend принимает только платформы `youtube`, `instagram`, `tiktok`, `generic` и ограниченный набор кодов (`unsupported_url`, `invalid_url`, `auth_required`, `private_video`, `source_rate_limited`, `download_error`, `network_error`, `too_large`, `too_long`, `send_error`, `busy`, `internal_error` и другие предусмотренные спецификацией).

**Состояние виджета:** `{"v":1,"p":"instagram","e":"auth_required"}`.

В состояние **не передаются** URL, Telegram user IDs, ошибки `yt-dlp`, cookies или access tokens. Тексты ошибок определяются на клиенте статической таблицей по заранее разрешённому коду.

HTML/CSS/JavaScript целиком встроены в бинарник Go, до 32768 байт исходника и 4096 байт сжатого zlib level 9. **Сеть из виджета недоступна; любые внешние ресурсы отсутствуют.**

## Флаги и этапы выпуска

```dotenv
# Общая система Live Download из этапа 3
DOWNLOAD_WIDGET_ENABLED=true

# Пилотная группа: пока только владелец, не трогать до успешной проверки
DOWNLOAD_WIDGET_PILOT_IDS=665731091

# Отдельный флаг ошибок (по умолчанию false в репозитории)
ERROR_WIDGET_ENABLED=false
```

1. Дождаться успешных `Go tests and vet`, `Docker build` и мёрджа PR.
2. После мёрджа включить на VPS `ERROR_WIDGET_ENABLED=true` при сохранении `DOWNLOAD_WIDGET_PILOT_IDS=665731091`, штатно пересоздать bot-контейнер.
3. В личном чате владельца проверить карточку «Неподдерживаемая ссылка» обычным URL на неподдерживаемый домен; раскрыть справку. Сложные ошибки (private/auth/429/timeout/50MiB) воспроизвести только когда есть реальные корректные примеры либо на disposable тестовом стенде.
4. Проверить обычную новую ссылку любой платформы: Live Download Widget всё ещё показывает прогресс, после успеха остаётся видео. Убедиться, что `/stats` и группы не изменились.
5. **После подтверждения владельцем** убрать ограничение `DOWNLOAD_WIDGET_PILOT_IDS` (пустое значение = все пользователи) и выполнить штатный деплой. Включённые одновременно `DOWNLOAD_WIDGET_ENABLED=true` и `ERROR_WIDGET_ENABLED=true` обеспечивают полную функциональность в приватных чатах для всех.

**Откат:** вернуть `ERROR_WIDGET_ENABLED=false` — ошибки станут прежними текстовыми, Live Download Widget продолжит работать. Для полного отката обоих этапов дополнительно установить `DOWNLOAD_WIDGET_ENABLED=false` и сделать штатный деплой. Никогда не запускать два экземпляра бота с одним `BOT_TOKEN`.

## Проверки

- Юнит-тесты: все платформы, белый список кодов, запрет Retry, статическая кнопка без сетевых запросов, лимиты размера HTML и state, текстовый fallback.
- Fake Telegram HTTP API: отправка Error Widget; при отказе — только один обычный текст; после сбоя загрузки прогресс-виджет удаляется, error-card остаётся; без двух одинаковых ошибок.
- Интеграционный тест на **одноразовой PostgreSQL-схеме**: mock `yt-dlp` воспроизводит private/429/network для трёх платформ; одна `media_requests` запись на попытку; нет дублированных text-сообщений. Ни один тест не должен подключаться к production БД.
- Проверка в реальном Telegram остаётся обязательной перед публичным развёртыванием.
