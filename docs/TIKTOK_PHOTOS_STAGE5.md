# Stage 5 — TikTok Photo Posts

Статус: код и интеграционные тесты готовы, выпуск только через отдельный feature flag. За основу взяты [WIDGETS_SPEC_V1.md](WIDGETS_SPEC_V1.md), [DOWNLOAD_WIDGET_STAGE3.md](DOWNLOAD_WIDGET_STAGE3.md), [ERROR_WIDGET_STAGE4.md](ERROR_WIDGET_STAGE4.md).

## Что делает бот

Поддерживаются **публичные TikTok-фотопубликации** формата
`https://www.tiktok.com/@user/photo/<numeric-id>` и сокращённые
`https://vt.tiktok.com/<code>/`, `vm.tiktok.com`, которые на них указывают.

1. Пользователь присылает ссылку. Для сокращённой TikTok-ссылки бот выполняет **ограниченный HTTPS HEAD** с проверкой хоста каждого редиректа. Только если целевой URL — TikTok `/@user/photo/ID`, он направляет его в обработчик фотографий. Обычные TikTok-видео продолжают работать через текущий `yt-dlp` без изменения аргументов.
2. Отдельный `gallery-dl` скачивает только фотографии (никаких видео/аудио/обложек) в ограниченную временную папку, без конфигов или пользовательских cookies.
3. Бот отправляет в том же порядке **одну фотографию через `sendPhoto`** или **альбомы по 2–10 фотографий через `sendMediaGroup`**, включая случаи 11, 21 и 35 фотографий, когда последний остаток идёт отдельным фото.
4. После успешной отправки сохраняются Telegram `file_id` в отдельной таблице `photo_album_caches` (ключ `tiktok-photo:<numeric-id>`). Повторные запросы доставляют фото из Telegram-кэша без `gallery-dl` и без временного статуса.
5. Музыка/аудио TikTok, если прикреплены к фотопубликации, **не скачиваются**.

**Именно ссылка пользователя** `https://vt.tiktok.com/ZSpaTVxRj/` была проверена на VPS: она перенаправляет к `@isisusisp/photo/7706556456627096852`; реальный `gallery-dl 1.32.19` и Go-обработчик успешно скачали одно изображение (134538 байт). Поэтому по ней бот должен использовать `sendPhoto`, а не `sendMediaGroup`.

## Отображение статуса

- **Группы:** без изменений, прежнее одно короткое сообщение **«⏳ сек, качаю»**, оно удаляется после отправки/ошибки. **Никаких** «4 из 8», процентов, новых виджетов и дополнительных промежуточных сообщений.
- **Личные чаты:** проверенный Live Download Widget с подписью **TikTok · Фото** и этапами «Скачиваем фотографии» / «Отправляем фотографии». Проценты загрузки фотографий не выдумываются — отображается неопределённая анимация, 100% только после успешной отправки всех элементов.
- **Ошибки:** существующие безопасные карточки (для групп — текстовый fallback), включая «Не удалось получить фотографии», «Очень много фотографий», «Слишком большие фотографии», «Не удалось отправить». Без Retry.
- **Кэш-хит:** временный статус не показывается, файл(ы) отправляются сразу.

## Безопасность и ограничители

- Отдельные `TIKTOK_PHOTO_ENABLED=false` и `TIKTOK_PHOTO_PILOT_IDS=` (пустой allowlist при включённом флаге = всем). Пробный запуск только на Telegram ID владельца `665731091`, затем — отдельное решение о публичном включении.
- **35 изображений максимум**; попытки получить 36 и более завершаются ошибкой, без усечения альбома.
- До **10 МиБ на фотографию**, до **80 МиБ на весь пост**, загрузка через `gallery-dl` — до 120 секунд; запрос на TikTok — только HTTPS из `*.tiktok.com`, с закрытым списком путей `/@user/photo/numericID`.
- Все фото записываются во временный каталог с безопасными фиксированными именами, symlink/неожиданные расширения/недостающие порядковые номера отклоняются; WebP конвертируется через установленный FFmpeg.
- Ограничение 1 активного запроса на пользователя, cooldown 3/30 сек, глобальная очередь и групповой rate limit используются те же, что для видео.
- Кэш фотографий **не меняет `media_cache`** и не увеличивает историческую метрику видео; один фото-пост является **одним `media_requests`-запросом**, вне зависимости от количества изображений. Пользователи учитываются по отдельным Telegram ID, в том числе в группах.
- Возврат устаревших file IDs или ошибка отправки дают понятный отказ без автоматического повторного скачивания или дублирующей пересылки.

## Инфраструктура и проверки

- Docker runtime: `gallery-dl==1.32.19` добавлен рядом с уже закреплённым `yt-dlp`. Go остается основным backend; Python-процесс — только изолированный extractor.
- Unit: TikTok photo URL и SSRF/неправильные redirects, fake gallery-dl, timeouts, разрывы в нумерации, лимит количества и размера, отправка 1/2/10/11/20/21/35 фото, Telegram cached IDs, status cleanup.
- E2E: fake Telegram API + disposable PostgreSQL schema + fake extractor, проверка двух пользователей и кэша, отсутствия загрязнения видеостата и удаления временного сообщения.
- Продакшн: только после зелёного CI/сборки и успешной ручной проверки владельцем новой фотоссылки; не запускать два экземпляра бота с одним токеном.
- **Откат:** `TIKTOK_PHOTO_ENABLED=false` и штатный перезапуск bot. Видео, аналитика и остальные виджеты остаются включёнными.
