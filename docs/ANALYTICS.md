# Аналитика xa4y_vidsave_bot

## Показатели
Историческая таблица `media_cache` содержит ссылки (source key), Telegram file ID и счётчик обращений, но не Telegram ID пользователей. Число пользователей и точные отправки до запуска новой аналитики восстановить нельзя.

Новая таблица `bot_users` хранит только числовой Telegram ID, время первого и последнего взаимодействия. `media_requests` хранит одну запись на каждый принятый запрос скачивания: Telegram ID, платформу, тип чата, статус, тип кэша, длительность и момент выполнения. **URL, usernames, сообщения и медиа не записываются.**

DAU/WAU/MAU — уникальные пользователи за скользящие 24 часа, 7 и 30 дней. В группах учитываются только взаимодействия с ботом (команды и поддерживаемые ссылки); в личном чате учитывается прямое обращение и inline-запросы. Успех — Telegram Bot API подтвердил отправку видео; ошибка — обработанный запрос не завершился отправкой. Процент успеха = success / total. Прошлые запросы не входят в новые счётчики.

## Владелец и /stats

1. В личном чате бота отправь `/id`, чтобы узнать Telegram user ID.
2. На VPS добавь в `/root/project/xa4y_vidsave_bot/.env` параметр `ADMIN_TELEGRAM_IDS=<твой ID>`; допускается несколько ID через запятую.
3. Обнови контейнер без пересборки: `cd /root/project/xa4y_vidsave_bot && docker compose up -d --no-deps --force-recreate bot`.
4. В том же личном чате отправь `/stats`.

Без указанного ID /stats **закрыта для всех**. Только точное совпадение поля `message.from.id` с разрешённым числом в личном чате открывает отчёт. Имя пользователя, админство в группе и настройка BotFather не являются проверкой доступа. Публичное меню содержит /start, /help, /id, а /stats показывается только в индивидуальном меню владельца.

## Доступ для ChatGPT с VPS

`cmd/stats` формирует агрегированный JSON через отдельное подключение к PostgreSQL. Не использует BOT_TOKEN, не делает миграций и не модифицирует данные. Для этого выделяется отдельный PostgreSQL пользователь только с SELECT и приватная строка подключения в `/home/chatgpt-work/.config/vidsave/readonly.env` (0600).

Использование: `scripts/metrics-readonly.sh` из корня проекта на VPS. Эта команда использует `VIDSAVE_STATS_DATABASE_URL` из файла и выполняет `go run ./cmd/stats`. Не печатай пароли, не коммить .env.

Изменения проверяются через `go test ./...` (отдельная БД в CI) и `go vet ./...`. Старую `media_cache` миграции не удаляют.

## Встроенный локальный API без паролей

В Docker Compose бот слушает `127.0.0.1:18873` в режиме `network_mode: host`. Сервер отклоняет адреса, отличные от loopback IP. Эндпоинты только для чтения:

- `GET /healthz` — ответ `ok`.
- `GET /stats` — агрегированный JSON по пользователям, запросам и платформам, без Telegram ID и исходных ссылок.

На VPS через Desktop Commander: `curl --fail http://127.0.0.1:18873/stats`. Это предпочтительный способ получения отчёта из ChatGPT, не требующий отдельной учетной записи в PostgreSQL. Порт не должен проксироваться через Nginx или публиковаться в интернет. Админская команда в Telegram независимо проверяет `ADMIN_TELEGRAM_IDS`.
